# 怪兽仙境 Remake · 整体立项书

立项日期：2026-10-13。范围升级依据：用户要求在 Unity 中重写完整怪兽仙境，在原有基础上扩展剧情、角色、怪兽、战斗等系统，继续沿用建筑风格、迷宫样式和宝箱设计；用户进一步明确继续 2D，保留俯视地图和角色精灵。

本文件是当前项目目标与范围的主入口。[系统设计](SYSTEMS.md)定义实现边界，[制作路线](ROADMAP.md)定义任务顺序与验收。历史土之秘境说明保留在 [PROTOTYPE_BASELINE.md](PROTOTYPE_BASELINE.md)。

## 1. 产品目标

在现有唯一仓库和 `Unity/` 工程中，以 C# 重写一个可独立运行、具有完整主线起止和成长循环的电脑端单机 RPG。延续原作的俯视探索、迷宫寻宝、主角与怪兽共同回合战斗、收服与培养，再扩展故事、人物关系、怪兽生态和战术选择。

最终交付是完整游戏。土之秘境是首个可验收章节，用来验证完整系统与制作方法；现有通关原型继续保留，后续逐步替换实现与资源。

核心体验：在城镇接取目标、整备队伍 → 探索野外与多层迷宫 → 战斗、收服、发现隐藏道与宝箱 → 培养、装备与合成 → 推进剧情、挑战守护者 → 解锁后续区域与支线 → 完成主线终局，并可继续探索未完成内容。

## 2. 已确定的制作约束

|项目|立项决定|验收依据|
|---|---|---|
|引擎与表现|Unity，2D 俯视探索，角色使用精灵；现有编辑器基线为 6000.3.0f1|实际地图与战斗场景可玩|
|建筑风格|延续原版建筑轮廓、屋顶、墙面、材质配色与门窗语言；允许提高绘制精度|原版与重制实景对照，新建筑与原建筑属于同一风格|
|迷宫样式|延续原版地形图块语言、通道尺度感、上下层、楼梯、隐藏道与区域连接方式|关键路线、层级和地标可辨认；新增区域遵循同样规则|
|宝箱设计|延续普通箱与大箱的外形、材质、尺寸关系和场景辨识度|原版/新版对照，开闭状态与实际地图尺度检查|
|角色与怪兽|保留原有识别特征；在角色关系、台词、成长与新增种类上扩展|每个原角色有参考与审核记录；新增内容明确标注|
|主角|奥尼克使用枪；认可的 v4 自然双枪造型作为基线；跑图与战斗比例独立|身体、武器分层，各型号和握持姿势独立|
|八宝|固定剧情同伴，独立于可收服怪兽与参战槽|切换出战怪兽不改变八宝，跟随与剧情身份一致|
|美术流程|一个角色一个角色审核，认可造型后制作动作|人类认可证据与技术验证分别记录|
|工程|沿用本仓库，日常分支使用 `codex/`，代码和 `.meta` 一同维护|保留可玩基础和版本对应的验证记录|

“沿用”包括原版环境的设计语言与辨识度，不要求永久保留低分辨率文件。建筑和宝箱可重绘清晰版本，迷宫可增加支路、机关与区域；改动必须记录原版依据和新增设计，保留核心路线和地标。新增环境资源先在一个实际场景中对照，再推广。

## 3. 内容与系统范围

|模块|需要承接的原有内容|本项目扩展范围|完成条件|
|---|---|---|---|
|主线剧情|奥尼克、八宝、驯兽师考试及包内可追溯事件与人物关系|补足人物动机、章节衔接和伏笔回收，写出完整结局；缺失资料段落采用明确标注的新编内容|从正式开场到结局可连续游玩，无开发指令解锁|
|支线与人物|原 NPC、商店、导师与可确认的支线|人物个人故事、同伴对话、区域委托与主线后的变化|支线可接取、推进、完成、读档恢复，奖励一次结算|
|世界与探索|现有城镇/野外/秘境地图资料、上下层和隐藏通道|同风格新支路、区域事件、机关与探索奖励|入口到目标及返程可达，不产生剧情软锁|
|角色表现|主角两套比例、原怪兽与八宝外形约束|独立动作、表情与关键剧情演出；新角色建立新档案|逐角色审核与实际运行检查齐全|
|怪兽与图鉴|本地 50 只原怪兽，五系阶层与特殊种|生态分布、专属技能、培养差异；新增怪兽作为扩展批次|原 50 只身份保留，收服/培养/合成闭环可用|
|战斗|主角带一只出战怪兽、最多三敌的回合结构与五系克制|完整技能与状态、行动顺序、怪兽职责、主角武器战术、Boss 阶段|结算规则可验证，演出不重复结算伤害，界面能说明结果|
|培养与合成|有证据的成长、性格相关资料和合成设定|清晰的成长路线、配方发现与技能搭配|预览成本与产物，确认后原子提交，无丢失或复制资产|
|装备与经济|原物品、武器、消耗品和商店资料|完整装备玩法、区域商店、任务奖励与资源节奏|装备数值与外观一致；双枪呈现不重复叠加一个槽的属性|
|八宝能力|原版跟随、照明、回城及移动相关证据|剧情互动、探索辅助；逐项设计能力条件和反馈|与队伍和任务系统协作，技能获得前不破坏关卡限制|
|界面与存档|中文操作、地图、队伍、行囊、图鉴与现有记录|任务日志、技能/装备/合成界面、设置、多存档与迁移|新开档、存档、读档、跨章推进完整可用|
|音频与演出|本地可确认的音频资料和原版战斗氛围|区域音乐、战斗反馈、关键剧情演出|支持音量控制，循环与场景切换正常|

第一版交付以电脑端离线单机为范围，当前实际构建平台为 Mac；Windows 为后续平台规划候选，纳入正式交付前需完成平台工作量与验证安排。联网对战、服务端运营、手机版本不进入当前必做范围。原版对联网资源的依赖由离线内容与明确的改编方案处理。

保留单只出战怪兽作为第一版核心规则；多人组队战斗、自由切换战斗制式等会改变整体体验的方案，需要单独设计后再进入制作范围。

## 5. 当前资产与差距

截至立项，已有土之秘境三层 27 区域、69 条出口记录、28 个箱子，探索/战斗/收服/守护者/碎片交付/存档的可玩闭环。地图 45 使用记录过的碰撞兼容覆盖，部分伤害与 Boss 数值为试玩适配；22 个已恢复奖励的箱子中有 1 个在当前普通路线不可交互，另外 6 个箱子奖励未恢复。以上均需带着差异进入后续章节验收。

主角 v4 造型已认可，v5 动作已接入且有技术记录，视觉认可另行确认。原 50 只怪兽仍使用旧 v1 占位。八宝 v2 造型已认可，v3 动作与独立跟随已接入且有技术运行记录；动作视觉认可另行确认。原有历史基线的参战怪兽跟随已被固定同伴替换，具体版本证据见八宝档案。立项不改写已有认可证据，也不把技术通过视为视觉认可。

整体立项后的首批推进已完成本地原资料逐项清单，并开始原事件条件分析和首章数据化任务模块；进度与差距见 [内容清单](Content/README.md) 和 [制作路线](ROADMAP.md)。

代码已有地图、存档、战斗、界面和主角动作模块；探索、剧情条件、战斗与菜单仍大量集中在 `EarthGame2D` 中。完整游戏需逐步拆分为可独立测试和制作内容的模块，避免每个新章节复制一份原型脚本。

## 6. 制作策略与版本门槛

按“系统核心 → 土之秘境完整切片 → 序章与章节串联 → 其余章节和终局 → 全程验收”推进。系统功能每次在现有章节中完成闭环验证，再用于后续内容；美术保持逐角色审核。

|版本门槛|必须交付的成果|
|---|---|
|立项基线|整体目标、保留/扩展边界、原版缺口、系统职责、任务顺序和验收条件有记录|
|核心系统可制作|剧情、任务、地图、战斗、成长、存档拥有稳定数据与调用边界，现有章节仍可通关|
|首章完整切片|土之秘境包含正式目标与成长入口、八宝、技能/状态、装备/培养、认可资源与完整操作闭环|
|全主线 Alpha|正式开场至终局可达，所有必需章节和主线系统可用；允许明确登记的资源占位|
|内容 Beta|原 50 只与计划新增内容、支线、演出、音频、正式资源按清单完成，流程与平衡经手工游玩|
|完整版本|全程通关、存读档、失败重试、支线回收、构建与平台验证完成，无阻断级问题|

章节数、扩展怪兽数量、总时长、预算、人员配置和发布日期尚未估算。先完成章节清单与首章工作量记录，再制定排期；这些未定项不阻止核心系统与首章开发。

## 7. 验收与变更

- 每次验证记录 Git 提交、资源版本、构建平台、存档版本、验证方式和结果。历史报告只证明对应版本。
- 自动检查覆盖路线、任务条件、结算、收服、合成和存档；手工检查覆盖键鼠操作、节奏、提示、视觉与音频。技术通过不授予美术认可。
- 全程验收从正式新开档开始，不能用试玩初始 10 级队伍、测试传送或直接改任务旗标替代实际成长流程。
- 完整游戏允许旧 2D 原型保留为回归基础；每个系统迁移必须验证既有土之秘境行为，并说明有意调整的玩法。
- 扩展剧情与系统功能可按本立项推进；角色造型仍遵循逐个审核。改变 2D 方向、建筑/迷宫/宝箱风格、主角身份或核心出战结构时，先提交具体对照与影响说明。
