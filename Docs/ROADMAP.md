## 3. 章节扩展的统一交付包

每章都有以下成果，按同一清单检查：

1. 章节设计：目标、人物变化、主线事件、支线、入口/出口条件与和下一章的衔接。
2. 来源与改编表：原版脚本/地图/物品依据，缺失资料，适配与扩展理由。
3. 关卡数据：地图、连接、上下层、遭遇、宝箱、机关、能力门槛与返程路线。
4. 战斗与经济：等级范围、敌人职责、技能、Boss、奖励、商店与合成需求。
5. 资源包：角色与怪兽审核、动作、原风格环境、UI、音效与音乐。
6. 验证包：从上章存档进入、本章主线/支线、失败恢复、返程、下一章解锁、存读档、人工体验。

章节数量和先后由 A02 事件图决定。五系原有分类不直接等于已确认的五个完整剧情章节；地图和脚本解析数量也不作为游戏时长承诺。

## 4. 版本证据与完成判定

|检查类型|最低覆盖|
|---|---|
|原版资料|哈希、引用存在、已核实/未核实语义、缺失资料登记|
|关卡|必需路线、楼层、门口、隐藏道、奖励触达、能力获得前后与返程|
|规则|技能和状态时序、异常目标、奖励去重、收服、经济、装备回滚、合成事务|
|存档|新档、旧档迁移、重复读档、跨章、备份与异常恢复|
|表现|原版建筑/迷宫/宝箱对照、角色尺度/锚点/方向/透明边缘、动画连贯与UI可读|
|人工体验|真实键鼠、教学、难度、失败重试、探索提示、音频与全程节奏|
|构建|目标平台实际启动、离线运行、保存位置与清晰操作说明|

报告至少写提交号、资源版本、平台、存档版本、用例、结果与剩余问题；脏工作区需列出未提交内容。不得把历史通关报告复制成新版本验证。

## 5. 工作量与风险处理

- 首章完成前记录每个系统和角色的实际制作工作量，之后按章估算内容与验证成本；不先承诺总时长或发布日期。
- 缺失原剧情：先调查已有证据，未取得部分采用可追溯的新编承接方案，提前在事件图中标明。
- 规则集中在原型脚本：分模块迁移并保留章节回归，每次只切换一个已验证边界。
- 美术审核工作量：按章节出现顺序逐个制作，优先保证首章必要角色，新增种类按生态与玩法需求立项。
- 关卡适配与原版差异：保存原数据，覆盖单独登记；不可达奖励逐项解释或修正，不自动丢弃。
- 存档变化：稳定内容/个体 ID，先设计迁移再改结构；不覆盖个人记录做实验。
- 跨平台交付：当前验证 Mac；后续正式纳入 Windows 时独立验证，字体、输入、文件路径、全屏与分辨率都纳入验收。

新增具体内容、日历排期与平衡参数在阶段成果中逐步固定；本路线的阶段范围和验收条件可立即指导开发。
