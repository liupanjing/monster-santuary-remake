# 怪兽仙境 Remake · 系统设计基线

日期：2026-10-13。本文承接 [整体立项](PROJECT.md)，定义后续实现方案，尚不代表以下系统均已开发。用户已确定 Unity 2D、原作基础上的内容和玩法扩展、延续环境风格；以下战术细节为首版设计提案，需在土之秘境中验证后固定。

## 1. 技术与数据边界

继续在当前 `Unity/` 工程中开发。当前版本、渲染和输入方式按现有工程基线推进；需要更换包或渲染管线时另列影响和迁移验证。新系统使用清晰的 C# 类型和职责边界，不要求为了立项一次重建全部场景。

数据定义存内容身份、配置和来源；运行实例存 HP、任务进度、开箱状态等变化；Unity 表现层负责精灵、镜头、UI 和音效。规则结算生成结果与事件，表现播放不拥有奖励、伤害或剧情解锁权限。

|模块|职责|与当前工程的关系|
|---|---|---|
|游戏流程|开场、探索、对话、战斗、菜单、章节与终局状态切换|逐步抽离 `EarthGame2D` 的状态与流程分支|
|内容目录|地图、人物、怪兽、技能、物品、配方、任务的稳定 ID 和引用|承接 `EarthData` 与 Resources/Data，保留原 ID|
|世界与地图|碰撞、上下层、区域门口、NPC、宝箱、遭遇、探索机关|沿用现有地图恢复结果，分离原数据与适配覆盖|
|剧情与任务|条件、事件、对话、旗标、任务状态、章节解锁|替代散落的固定对话与布尔判断，原脚本先逐项映射|
|战斗规则|行动合法性、顺序、命中/效果/状态/胜负、奖励|由纯C# `AtbBattle` 执行，章节适配器只接入与播放|
|队伍与成长|个体实例、出战槽、经验、性格、技能、合成|保留 `Unit` 与队伍迁移入口，新增稳定个体 ID|
|装备与经济|装备效果、商店、物品使用、交易、配方成本|联动既有 WeaponDefinition2D，外形与数值分别配置|
|固定同伴|八宝跟随、切图、楼层、剧情与探索能力|从 `Pet` / `activePet` 参战槽中独立出来|
|存档|版本、迁移、原子写入、备份、读档校验|承接现有 v2/v3 记录与 SaveFile|
|表现与界面|角色动作、武器、VFX、对话、地图、日志、音频|保留现有主角动作和分层武器，UI 订阅状态与结果|

建议新增功能目录位于 `Assets/Remake/Scripts/` 内，按模块逐步组织。地图与配置采用适合已有工具的 JSON，编辑器可配置资源采用 ScriptableObject；内容转换应生成稳定产物与来源记录，不在运行时执行反编译脚本。

## 2. 剧情、任务与内容扩展

先整理原版事件链：人物 → 地点 → 前置条件 → 对话/演出 → 战斗/选择 → 结果 → 后继事件。每条事件记录原脚本文件与偏移；缺失链路明确标注，不能根据地图编号自动编出章节顺序。

任务最小状态为未接取、进行中、可交付、已完成，并支持阶段计数、一次性奖励及失败/恢复策略。事件通过条件读取状态，通过动作请求推进；条件至少覆盖任务阶段、物品、角色、区域、Boss、探索能力。对话与 UI 不直接修改存档字段。

扩展优先补人物动机和区域故事：八宝随行对话、导师教学、怪兽相关委托、城镇事件和章节后 NPC 变化。分支首版用于台词、支线解决方式与奖励选择；多结局与永久互斥主线暂不作为交付前提。

正式开场需要独立的新开档配置与教学流程，覆盖移动、交互、主角与怪兽战斗、收服、培养、任务与存档。现有 10 级起步仍作为开发试玩预设，不能当作正式开场。

## 3. 战斗规则：行动条制

2026-10-14 用户要求完全废弃旧系统，并明确选择速度推动行动条、角色到点后下令。当前运行已采用全新的纯C#规则、独立指令/目标、行动条UI与敌方决策；详细规则、技能来源与验证边界见 [行动条战斗](ATB_COMBAT.md)。旧 `ChapterCombat` 和双人回合队列已删除。

首版以主角＋一只出战怪兽、最多三敌接入现有章节。速度影响就绪频率，选指令和播放结果时暂停时间；动作自身有恢复代价与冷却。每次指令单独校验目标、消耗和合法性，结果以事件交给表现层。随机源与Unity分离，可按种子重放。怪兽按六类元素职责使用重制技能，守护者提供预告目标与半血阶段。

保留已核实的五系克制与角色成长数据。新技能、魔法防御换算、状态持续、AI与Boss数值属于明确标记的重制设计；95条原有名技能与37条原效果继续保留证据，不把新命名空间中的技能标为完整原版恢复。主角武器数值、逐物种专属技能、学习条件与协同指令后续逐批扩展。

收服、死亡和移除使用独立遭遇ID；永久个体ID仍待存档模块实现。双枪动画只消费一次已结算结果，不能重复扣血。八宝继续独立于参战槽，美术审核约定不因战斗重写改变。

## 4. 怪兽、培养、装备与经济

原 50 只怪兽的身份、五系阶层和独特外形继续保留。图鉴记录可见/遇见/收服、栖息地、技能与合成线索。新增种类使用独立 ID，以章节生态和战术缺口为依据分批规划，不覆盖原怪兽。

成长保留已确认的整数运算来源，重制调整作为独立平衡配置。性格、亲和、培养项目先核对证据和玩法收益；首版优先完成经验、技能学习与配方合成，再增加更多培养维度。

合成有两个流程：预览（素材个体、货币、产物、继承规则）和提交（校验 → 扣除 → 创建个体 → 写入）。拒绝把唯一可用出战怪兽消耗到无法继续游戏；重复点击和读档不能复制产物。原配方与新增配方分别标注。

装备使用独立物品定义和武器外观定义。主角仍为原版一个武器槽的基线，双枪是视觉呈现；特殊武器不能复制双枪姿势。库存、装备属性、技能解锁和外观变更作为一个操作提交，失败则全部保持原状态。

经济围绕每章补给、收服、培养与装备成本制作表格，记录收入来源与支出。稀有宝箱、主线奖励、商店货物和合成材料共同规划，先检查玩家正常路线是否能完成必要成长，再调整数值。

## 5. 地图、建筑、迷宫与宝箱

原图保留在证据目录；运行地图允许引用有记录的兼容覆盖。地图制作必须同时检查图块画面、通行属性、上下层触发、门口、返程和剧情能力限制。保留土之秘境既有路线检查，并扩展到其他章节。

制作环境风格表时，从包内提取城镇建筑、地形、普通箱与大箱的参考，记录轮廓、比例、材质、配色和地图中的占格。新图块必须匹配格子尺度、透视与层级；光效不能让楼梯、暗路和可交互对象失去可读性。

迷宫扩展先用一张地图验证新支路、机关和隐藏奖励，保留关键入口、守护者方向与上下层阅读方式。正式地图和开发测试地图分开标识；章节关卡登记入口条件、关键道具、软锁检查及返程方案。

宝箱身份为稳定 `mapId + chestId`；奖励定义与箱体表现分离。首次开启发放一次奖励并写入状态，跨图/读档保留；奖励未恢复的原箱在调查清单中保留，新填奖励标为重制设计。普通箱与大箱分别制作关闭、打开与反馈表现。

## 6. 八宝与角色资源

八宝使用固定 companionId，不占怪兽收服计数或参战槽。跟随采用主角路径历史与受控追赶，处理门口、上下层、楼梯、遮挡、对话、战斗隐藏/恢复；不得穿过阻挡成为路线提示错误。四方向悬浮与扇翅基于认可造型制作，参战怪兽切换不替换八宝。

照明、回城、移动等能力由剧情授予，记录可用区域、费用/冷却和禁用条件；原版特殊帧的用途先核对，再决定表现。八宝能力扩展与怪兽探索技能要在关卡条件中统一检查。

主角保持跑图 Q 版、战斗身体两套独立资源。身体、握点、武器、遮挡、枪口分别管理；怪兽逐只制作待机、行动、受击及必要方向。审核状态记录在现有角色档案，新增角色同样建立原型/提案与认可记录。

## 7. 存档、工具与验证

正式存档包含 schemaVersion、内容版本、队伍个体、技能、装备、库存、世界旗标、任务阶段、已开箱、角色位置与探索能力。升级新增版本而不复用字段意义；保留 v2/v3 样本和迁移测试。无法自动映射的变化需备份并给出明确恢复方式。

开发工具提供内容引用检查、事件链预览、地图路线、技能效果检查、战斗重放和验证报告。调试快捷入口不进入正式任务奖励逻辑；自动用例使用独立存档目录。

必须验证：条件达成/未达成的任务分支、奖励重复领取、异常目标、同时死亡、收服后行动条与目标、状态到期、合成失败、装备回滚、八宝切图、上下层、旧档迁移和完整章节返程。视觉与人工操作验证另列，不由规则测试替代。
